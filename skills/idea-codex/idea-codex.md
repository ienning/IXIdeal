# Idea to Project Skill（Codex 版）

> **平台说明**：本 Skill 适用于 OpenAI Codex CLI。
> 如果你使用 Claude Code，请使用 `skills/idea/idea.md`。

## 前置要求

在 `~/.codex/config.toml` 中确保已启用多代理支持：

```toml
[features]
multi_agent = true
```

## 触发方式

- `/idea-codex` — 从零开始，进入 Phase A 对话引导
- `/idea-codex <文件路径>` — 读取已有模板，智能路由

## 工具映射

本 Skill 使用以下 Codex 原生工具：

| 操作 | Codex 工具 |
|------|-----------|
| 读取文件 | 原生文件读取工具 |
| 写入/编辑文件 | 原生文件写入工具 |
| 网络搜索 | 原生搜索工具（如已配置）|
| 子代理（如需）| `spawn_agent` + `wait` + `close_agent` |
| 任务跟踪 | `update_plan` |

---

## 行为准则

- 每次只问一个问题，等待用户回答后再继续
- 语气友好，为每个字段提供简短的填写示例
- 用户每回答一个字段，立即用原生文件编辑工具写入模板文件
- Phase B 搜索时尽量并行执行 GitHub 和 Web 搜索
- 分析结果写入模板文件 `<!-- ANALYSIS_START -->` 和 `<!-- ANALYSIS_END -->` 之间

---

## 启动路由逻辑

```
1. 是否传入了文件路径？
   ├─ 是：读取文件，统计 8 个字段中有实质内容（非空、非仅有 -）的数量
   │     ├─ ≥6 个字段有内容 → 告知"信息充分，直接开始分析" → Phase B
   │     └─ <6 个字段有内容 → 告知"我来帮你补全空字段" → Phase A（仅问空字段）
   └─ 否：告知将创建新文件 idea-YYYY-MM-DD.md → 创建模板 → Phase A
```

## Phase A：对话引导

按顺序逐一引导，每次只问一个字段：

**字段 1 — 核心想法**
> "先从最重要的开始——用一两句话告诉我你想做什么？"
> 示例：我想做一个帮助独立开发者自动记录工作时间的命令行工具

**字段 2 — 目标用户**
> "这个产品主要给谁用？他们是什么样的人？"
> 示例：独立开发者、自由职业者，同时维护多个项目

**字段 3 — 核心价值**
> "它能帮用户解决什么具体问题？"
> 示例：现有工具要么太复杂，要么无法自动识别工作内容

**字段 4 — 期望功能**
> "你希望它有哪些功能？想到什么说什么。"
> 示例：自动识别当前项目、手动打标签、每周生成摘要报告

**字段 5 — 技术偏好**
> "你有技术背景吗？倾向用什么语言或框架？"
> 示例：熟悉 Python；或：完全不懂技术

**字段 6 — 资源约束**
> "大概有多少时间、预算和人手？"
> 示例：个人项目，每周约 10 小时，无预算

**字段 7 — 成功标准**
> "第一个里程碑是什么？做到什么程度算成功了？"
> 示例：能在自己的电脑上稳定运行一个月

**字段 8 — 竞品参考**
> "市场上有没有类似产品？你喜欢或不喜欢哪些地方？"
> 示例：用过 Toggl，喜欢报表，不喜欢手动计时

用户回答后立即写入模板文件，所有字段完成后进入 Phase B。

## Phase B：深度分析

### Step 1：提取关键词

从模板内容中提取产品类型关键词（英文，用于搜索）、行业领域关键词、技术栈关键词。

### Step 2：搜索

如搜索工具可用，搜索以下内容：
- GitHub 方向：`site:github.com <产品类型英文> <技术栈>`
- 竞品方向：`<产品类型> alternatives 2024`

如搜索工具不可用，根据已有知识进行分析，并在结果中注明"基于训练数据，建议用户自行验证最新信息"。

### Step 3：生成分析结果

生成以下六个章节，写入模板文件的分析区：

1. **可行性评估**：技术/市场/资源三维度，🟢/🟡/🔴 评级 + 风险点
2. **技术方案**：推荐技术栈 + 架构思路 + 实现路径
3. **开源项目参考**：3-5 个相关项目表格 + 使用建议
4. **竞品分析**：3-5 个现有产品对比 + 差异化机会
5. **MVP 任务拆解**：10-15 个任务清单，区分 🔴 必须和 🟡 加分
6. **资源清单**：学习资料 + 工具 + 社区

### Step 4：完成告知

写入完成后告知用户分析已完成，文件路径，并询问是否需要深入探讨某个方面。
